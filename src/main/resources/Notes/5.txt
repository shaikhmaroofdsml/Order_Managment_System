# Phase 5: Non-Select Custom Queries (`@Modifying` + `@Transactional`)

Your notes explain that **`@Query` alone is enough for SELECT operations**, but for **UPDATE, DELETE, and INSERT** you must also use:

* `@Modifying`
* `@Transactional`



---

# Why Do We Need @Modifying?

Suppose you want to increase the stock of a product.

Instead of:

```java
Product product = repository.findById(id).get();
product.setStock(product.getStock() + 10);
repository.save(product);
```

You can execute a direct update query.

```sql
UPDATE products
SET stock = stock + 10
WHERE id = 1;
```

Spring Data JPA allows this using `@Query`.

---

# Step 1: Increase Stock

Repository

```java
@Modifying
@Transactional
@Query("""
UPDATE Product
SET stock = stock + :qty
WHERE id = :id
""")
int increaseStock(
        @Param("id") Long id,
        @Param("qty") Integer qty);
```

Returns

```text
1
```

means

```text
1 row updated
```

# Step 7: Native INSERT

Normally we use

```java
repository.save(product);
```

But for learning purposes:

```java
@Modifying
@Transactional
@Query(value="""
INSERT INTO products
(name,price,stock,description,category_id)
VALUES
(:name,:price,:stock,:description,:category)
""",
nativeQuery=true)
void insertProduct(
        @Param("name") String name,
        @Param("price") Double price,
        @Param("stock") Integer stock,
        @Param("description") String description,
        @Param("category") Long categoryId);
```

> **Note:** In real Spring Boot applications, `save()` is almost always preferred for inserts. Native `INSERT` queries are mainly used in special cases or for learning.

# Step 8: Soft Delete

Instead of deleting records permanently, mark them as inactive.

## Update Entity

```java
@Column(nullable = false)
private Boolean active = true;
```

Now the table becomes

```text
products

id

name

price

stock

active
```

---

Repository

```java
@Modifying
@Transactional
@Query("""
UPDATE Product
SET active=false
WHERE id=:id
""")
int softDelete(
        @Param("id") Long id);
```

Nothing is deleted.

Database

```text
Before

id=1

active=true
```

↓

After

```text
id=1

active=false
```

This follows the soft delete approach described in your notes.
