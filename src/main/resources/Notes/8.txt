# Step 1: Order Entity

```java
@Entity
@Table(name="orders")
@Getter
@Setter
@NoArgsConstructor
@AllArgsConstructor
@Builder
public class Orders {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private LocalDateTime orderDate;

    private Double totalAmount;

    private String status;

    @ManyToOne
    @JoinColumn(name="customer_id")
    private Customer customer;

    @OneToMany(mappedBy="order",
            cascade=CascadeType.ALL)
    private List<OrderItem> orderItems;

}
```

# Step 7: Why @Transactional?

Suppose customer buys

```text
Laptop

Phone

Keyboard
```

Flow

```text
Save Order

↓

Reduce Laptop Stock

↓

Reduce Phone Stock

↓

Payment Failed
```

Without transaction

```text
Order Saved

Stock Reduced

Payment Failed
```

Database becomes inconsistent.

---

With transaction

```text
Order Saved

↓

Stock Reduced

↓

Payment Failed

↓

Everything Rollback
```

Database returns to previous state.

# What Happens Internally?

```text
BEGIN TRANSACTION

↓

Save Order

↓

Save Order Items

↓

Update Product Stock

↓

Save Payment

↓

COMMIT
```

If any exception occurs:

```text
BEGIN

↓

Save Order

↓

Save Order Items

↓

Update Stock

↓

Payment Exception

↓

ROLLBACK
```

No partial data remains in the database.
