# Phase 10: Performance Optimization & Best Practices

# Why Performance Matters

Imagine your application has:

* 100,000 Products
* 50,000 Customers
* 500,000 Orders

If every request executes unnecessary SQL queries, your application will become slow even on powerful servers.

---

# 1. Lazy Loading vs Eager Loading

## Lazy Loading

```java
@ManyToOne(fetch = FetchType.LAZY)
@JoinColumn(name = "category_id")
private Category category;
```

Hibernate loads only the `Product`.

When you access:

```java
product.getCategory().getName();
```

then it executes another SQL query.

---

## Eager Loading

```java
@ManyToOne(fetch = FetchType.EAGER)
private Category category;
```

Hibernate immediately loads both Product and Category.

---

### Which One Should You Use?

| LAZY                   | EAGER                     |
| ---------------------- | ------------------------- |
| Loads only when needed | Loads immediately         |
| Better performance     | Can load unnecessary data |
| Recommended by default | Use only when required    |

---

# 2. The N+1 Query Problem

Suppose you have 100 products.

Code

```java
List<Product> products = repository.findAll();

for(Product product : products){
    System.out.println(product.getCategory().getName());
}
```

Generated SQL

```sql
SELECT * FROM products;
```

Then for each product:

```sql
SELECT * FROM categories WHERE id=?;
```

If there are 100 products:

```text
1 Query

+

100 Queries

=

101 Queries
```

This is called the **N+1 Query Problem**.

---

# 3. Solve N+1 with JOIN FETCH

Repository

```java
@Query("""
SELECT p
FROM Product p
JOIN FETCH p.category
""")
List<Product> findAllWithCategory();
```

Generated SQL

```sql
SELECT p.*, c.*
FROM products p
JOIN categories c
ON p.category_id = c.id;
```

Now only **one query** is executed.

---

# 4. Using @EntityGraph

Instead of writing a custom JPQL query:

```java
@EntityGraph(attributePaths = "category")
List<Product> findAll();
```

Spring automatically fetches the category together with the product.

This is often cleaner than `JOIN FETCH`.

---

# 5. Batch Inserts

Instead of:

```java
for(Product p : products){
    repository.save(p);
}
```

Use:

```java
repository.saveAll(products);
```

This reduces database round trips.

---

# 6. Batch Updates

Avoid:

```java
for(Product product : products){
    product.setPrice(product.getPrice() * 0.9);
    repository.save(product);
}
```

Prefer a bulk update:

```java
@Modifying
@Transactional
@Query("""
UPDATE Product
SET price = price * 0.90
""")
int applyDiscount();
```

One SQL statement updates every row.

---

# 7. Read-Only Transactions

For queries that only read data:

```java
@Transactional(readOnly = true)
public List<ProductResponse> getProducts() {
    return repository.findAll()
                     .stream()
                     .map(this::mapToResponse)
                     .toList();
}
```

This allows Spring and the persistence provider to optimize the transaction.

---

# 8. DTO Projection

Avoid returning complete entities if the client only needs a few fields.

Instead of:

```java
List<Product>
```

Return:

```java
public record ProductSummary(
    String name,
    Double price
){}
```

Repository

```java
@Query("""
SELECT new com.ecommerce.dto.ProductSummary(
    p.name,
    p.price
)
FROM Product p
""")
List<ProductSummary> summary();
```

Less data is transferred from the database.

---

# 9. Pagination Everywhere

Avoid:

```java
repository.findAll();
```

Prefer:

```java
repository.findAll(
    PageRequest.of(0, 20)
);
```

Never return thousands of rows in a single API response.

---

# 10. Avoid Business Logic in Controllers

❌ Bad

```java
@PostMapping
public void create() {
    // validation
    // save
    // payment
    // stock update
}
```

✅ Good

```java
@PostMapping
public OrderResponse create(
        @RequestBody OrderRequest request) {

    return orderService.placeOrder(request);
}
```

Business logic belongs in the service layer.

---

# 11. Handle Exceptions Centrally

Instead of writing `try/catch` in every controller, use:

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(RuntimeException.class)
    public ResponseEntity<String> handle(RuntimeException ex) {
        return ResponseEntity.badRequest()
                .body(ex.getMessage());
    }
}
```

---

# 12. Validate Input

DTO

```java
public class ProductRequest {

    @NotBlank
    private String name;

    @Positive
    private Double price;

    @Min(0)
    private Integer stock;
}
```

Controller

```java
@PostMapping
public ProductResponse create(
        @Valid @RequestBody ProductRequest request) {

    return service.create(request);
}
```

---

# 13. Logging

Instead of:

```java
System.out.println("Product saved");
```

Use:

```java
private static final Logger log =
        LoggerFactory.getLogger(ProductServiceImpl.class);

log.info("Product {} created", product.getName());
```

---

# 14. Common Repository Best Practices

* Extend `JpaRepository` instead of `CrudRepository` when you need pagination and sorting.
* Use derived query methods for simple queries.
* Use JPQL for entity-oriented custom queries.
* Use native SQL only when JPQL cannot express the query efficiently.
* Use `@Transactional` around business operations involving multiple database updates.
* Return DTOs from controllers instead of entities.
* Prefer constructor/record projections for reporting queries.
