# Phase 6: Pagination, Sorting & Filtering

Every large application (Amazon, Flipkart, Gmail, LinkedIn) uses pagination because loading thousands of records at once is inefficient. Your notes introduce these features through `JpaRepository`, `PageRequest`, `Page`, and `Sort`.

---

# Current Problem

Suppose your database has

```text
100000 Products
```

If the client calls

```http
GET /products
```

Spring loads all 100000 records.

Problems:

* Slow response
* High memory usage
* Poor user experience

Instead, load only a page of data.

---

Example


# Step 2: Service

```java
public Page<ProductResponse> getProducts(
        int page,
        int size){

    Pageable pageable = PageRequest.of(page,size);

    Page<Product> products =
            repository.findAll(pageable);

    return products.map(this::mapToResponse);

}
```

# Controller

```java
@GetMapping("/sort")

public List<ProductResponse> sort(

@RequestParam String field,

@RequestParam String direction){

    return service.sort(field,direction);

}
```

---

Service

```java
public List<ProductResponse> sort(
String field,
String direction){

Sort sort =
direction.equalsIgnoreCase("desc")
?
Sort.by(field).descending()
:
Sort.by(field).ascending();

return repository.findAll(sort)
.stream()
.map(this::mapToResponse)
.toList();

}
```

---

# API

Ascending

```http
GET /products/sort?field=price&direction=asc
```

Descending

```http
GET /products/sort?field=price&direction=desc
```

# Pagination + Sorting

Best practice

```java
public Page<ProductResponse> getProducts(

int page,

int size,

String field,

String direction){

Sort sort=
direction.equals("desc")

?

Sort.by(field).descending()

:

Sort.by(field).ascending();

Pageable pageable=
PageRequest.of(page,size,sort);

return repository
.findAll(pageable)
.map(this::mapToResponse);

}
```

---

API

```http
GET /products?page=0&size=5&field=price&direction=desc
```

---

Generated SQL

```sql
SELECT *
FROM products

ORDER BY price DESC

LIMIT 5 OFFSET 0;
```
